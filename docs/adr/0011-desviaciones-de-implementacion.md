# ADR 0011 — Desviaciones de implementación respecto al plan

- Estado: aceptada (2026-11-03)
- Fase: cierre de F10

## Contexto

Al revisar el plan contra el código al final de F10 aparecieron decisiones técnicas que se tomaron durante la implementación y no quedaron registradas. Este ADR las deja por escrito. Ninguna cambia lo que el usuario ve ni los presupuestos de §5.1, que la prueba de §5.3 sigue midiendo.

## Decisión

| Plan                                                                    | Implementación                                                                                                                                                                                                                                                           | Motivo                                                                                                                                                                                                                                                   |
| ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `packages/registry` (§4)                                                | La carga y validación de packs vive en `apps/local-service` (`libraries.ts`, `devices.ts`, `hooks-packs.ts`) y las consultas del catálogo en los stores de `apps/web/src/services`.                                                                                      | Solo había un consumidor por consulta; un paquete intermedio no aportaba reutilización. Se crea si Electron (ADR 0009) necesita las mismas consultas.                                                                                                    |
| `packages/importer` (§4)                                                | La detección del perfil (`detect.ts`) y los `parse` (`parse.ts`) viven en `packages/codegen`, junto a los `emit`; la orquestación en `apps/local-service/src/import.ts`.                                                                                                 | Cada códec tiene `emit` y `parse` (ADR 0003); tenerlos en el mismo paquete hace que las pruebas de propiedad `parse(emit(x)) = x` no crucen paquetes.                                                                                                    |
| Lienzo con @xyflow/react (§13.1)                                        | Lienzo propio en `apps/web/src/editor/Board.tsx`: cámara con transformaciones CSS, recorte a las pantallas visibles y nivel de detalle con zoom lejano.                                                                                                                  | Pan y zoom no pasan por React, lo que mantiene los 60 fps con `journey-50`; las conexiones son pocas y no necesitan el motor de grafos.                                                                                                                  |
| Arrastrar y soltar con dnd-kit (§11.2)                                  | Drag and drop nativo de HTML5 (`catalog-drag.ts`) más acciones de teclado equivalentes: agregar desde el catálogo con Enter y mover nodos con Alt+↑/↓.                                                                                                                   | El iframe de la vista previa ya reporta la geometría; el drag nativo cruza el borde del iframe sin capas extra. La accesibilidad se cubre con los atajos.                                                                                                |
| Import maps para compartir React (§7.1)                                 | El iframe expone `react`, `react-dom` y `react-native-web` en un global (`__rnjb`) y los bundles de librería los resuelven como `external` (`apps/local-service/src/bundle.ts`).                                                                                         | Mismo efecto (una sola instancia) sin depender de que el import map esté declarado antes de cualquier módulo del iframe.                                                                                                                                 |
| Formularios con React Hook Form y Yup en la vista previa (§14.1)        | RHF y Yup se usan en el código exportado. En la vista previa los errores de campo se simulan con datos (`simulate-errors.ts`).                                                                                                                                           | La vista previa no ejecuta código del documento (§2.8); ejecutar un schema Yup generado lo violaría.                                                                                                                                                     |
| Renombrar actualiza los derivados y avisa si ya se exportó (§9.2.4)     | Renombrar cambia solo el nombre visible (`renameJourney`). El slug queda fijo desde la creación, y con él el archivo, la carpeta, el paquete y los nombres del código.                                                                                                   | Cambiar el slug mueve el archivo y `assets/`, y obliga a migrar borradores, locks y pestañas abiertas (§18). Como los derivados exportados nunca cambian, no hace falta el aviso. Si se necesita, se agrega una acción «Cambiar slug» con su propio ADR. |
| Catálogo con lista virtualizada (§11.3)                                 | Cada fila del catálogo y de Bloques usa `content-visibility: auto` con un tamaño intrínseco de 28 px: el navegador no pinta ni calcula las filas fuera de la vista.                                                                                                      | Mismo efecto que una lista virtualizada para catálogos de cientos de componentes, sin otra dependencia ni cálculo de alturas en JS. Si un pack llega a miles de componentes, se cambia por `@tanstack/react-virtual`.                                    |
| Miniaturas generadas en inactividad y guardadas por hash (§13.2, §19.1) | Con zoom lejano el lienzo dibuja la estructura del árbol de cada pantalla (`FrameStructure`), y las tarjetas de Inicio dibujan el mapa del journey (`OutlineMap`, que viene en el índice). Ninguna de las dos renderiza la pantalla.                                     | Salen del documento sin render ni captura, así que no necesitan caché y cumplen los presupuestos de §5.1. Una miniatura real obligaría a renderizar cada pantalla en un iframe fuera de vista y capturarla.                                              |
| Worker threads para análisis, compilación y git (§5.2)                  | El análisis de TypeScript (`parseProject`, `extractManifest`) corre en un worker persistente (`off-thread.ts`), que conserva la caché por hash de `ts-analysis`. git se ejecuta como proceso aparte (`execFile`). La compilación con Vite queda en el proceso principal. | git ya no bloquea el hilo de Node. Vite delega el trabajo pesado a rolldown, que usa hilos nativos. En Vitest las tareas corren en el mismo hilo, porque ahí no hay loader de tsx para el worker.                                                        |

## Consecuencias

- La tabla de §4 del plan describe la intención; este ADR describe dónde vive hoy cada responsabilidad.
- Si una desviación deja de servir (por ejemplo, Electron necesita el catálogo fuera de la web), se crea el paquete que el plan nombraba y se actualiza este ADR.
